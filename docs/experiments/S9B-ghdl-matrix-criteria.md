# S9B GHDL WASM の最適化マトリクスの採用基準（測る前に固定）

- 決定日：2026-10-30
- 経緯：S9 で、Os + LTO は最初の条件（ビルドの成功）を満たしませんでした（`sqrt`・`sqrtf` の重複定義でリンクに失敗）。ユーザーの判断により、-O1 に戻さず、マトリクスで比べて決めます。
- 比較の基準（B0）：今の main の既定ビルド（Ada は -O1、C の wasi.c は -O2、LTO なし）

## 候補（Ada と C の wasi.c に同じレベルを使う）

| 名前 | コンパイル | リンク |
|---|---|---|
| O1 | -O1 | LTO なし |
| O2 | -O2 | LTO なし |
| O3 | -O3 | LTO なし |
| Os | -Os | LTO なし |
| O3+LTO | -O3 -flto | LTO 付き |
| Os+LTO | -Os -flto | LTO 付き（S9 の結果を引き継ぐ。再度は試さない） |

LTO の候補でリンクに失敗したら、その候補は失敗として記録し、回避の変更は加えません。

## 安定性の条件（候補ごと。すべて満たしたものだけが速さの比較に進む）

1. ビルドが成功する。
2. ゼロからのビルドを 2 回行い、`ghdl-synth.wasm` と `libraries.tar.gz` がバイト単位で一致する。
3. `tests/synth/ghdl-wasm.test.mjs` が 8/8 で、5 回続けて通る。
4. 6 つの例すべてで、ネイティブ版 GHDL と WASM の Verilog がバイト単位で一致する。
5. 4 ボードの VHDL から作った `.fs` が、ネイティブの経路とバイト単位で一致する。
6. 既存の負の対照が、候補でも失敗として検出される。

## 速さの比較

- 指標：Chromium（Playwright、S7 と同じ測り方）で、6 つの例の GHDL 合成時間（インスタンス化を含む）の中央値の合計。各案 5 回以上、案の順番は回ごとに入れ替える。
- 採用：安定性の条件を満たした案のうち、指標が最も小さい案。ただし、B0 より 3% 以上速く、その差が B0 の 5 回の幅（最大 - 最小）より大きいこと。満たす案がなければ B0 のままにする。
- 記録だけ：WASM の大きさ（生、gzip、zstd）、Node での同じ指標。
