# S9 GHDL WASM の Os + LTO 採用基準（測る前に固定）

- 決定日：2026-10-30（ユーザーの判断：速さのマトリクスは省き、Os + LTO の安定性だけを確かめる。不合格なら -O1 に戻さず、マトリクスで比べて決める）
- 比較の基準：PR #31 の head の既定ビルド（Ada・C とも `-O1`、LTO なし）
- 候補：Ada・C のコンパイルを `-Os -flto`、リンクを LTO 付き（wasm-ld）。ほかの条件は基準と同じ

## 合格の条件（すべて満たすこと）

1. 候補でビルドが成功する（AdaWebPack の `llvm-gcc` と WASI SDK の wasm-ld で LTO が使える）。LTO の効いた証拠（LTO の bitcode か、リンク時の LTO の実行）を記録する。
2. ゼロからのビルドを 2 回行い、`ghdl-synth.wasm` と `libraries.tar.gz` がバイト単位で一致する。
3. `tests/synth/ghdl-wasm.test.mjs` が 8/8 で、5 回続けて通る。
4. 6 つの例すべてで、ネイティブ版 GHDL と WASM の Verilog がバイト単位で一致する。
5. 4 ボードの VHDL から作った `.fs` が、ネイティブの経路とバイト単位で一致する（5 回）。
6. 既存の負の対照（壊した入力や期待値の改変）が、候補でも失敗として検出される。

## 記録するだけのもの（採否には使わない）

- WASM の大きさ（生、gzip、zstd）
- Node で、6 つの例の合成時間の中央値（5 回）。基準と候補を並べる

## 不合格のとき

候補を既定にしない。失敗の内容を記録し、作業を止めて報告する。マトリクス（-O1、O3 + LTO、Os、Os + LTO など）の基準は、別に固定してから測る。
