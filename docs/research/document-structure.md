# 文書を意味単位で分割する方針

[調査の索引へ戻る](../../RESEARCH.md#7-分割した調査)

## 調査と採否

文書は目的と読者で分けます。利用者の操作、開発者の保守、調査の採否、実験の再実行は、必要な説明と前提が異なります。一方、リンク先へ条件を追い出しすぎると、短い文書でも理解しにくくなります。

[Diataxis](https://diataxis.fr/) は、学習、手順、参照、説明を読者の必要に応じて区別します。[Googleのcross-reference指針](https://developers.google.com/style/cross-references)は、説明的なリンク名と、本文の文脈を保つ参照を勧めます。この考え方を採り入れます。既存の配置を全面的に改名したり、機械的に4種類へ振り分けたりはしません。

本リポジトリーでは、Gitで追跡する Markdown がUTF-8で20,000バイトを超えたら分割を検討し、40,000バイトを超えたら分割または理由付き例外を必須にします。数値は独自の提案としてユーザーが承認したものです。DiataxisやGoogleが定めた値ではありません。

元の規則はRESEARCHだけに40 KBの分割を求めていました。調査時にはMarkdownが43ファイルあり、RESEARCHは約37 KB、S5・S11は約30 KB、S14も20 KBを超えていました。警告の目安を半分の20,000バイトへ置き、全Markdownへ適用する案を採用します。20,000を一律の上限とする案は、実験条件と結果の断絶や過剰な細分化につながるため採用しません。

## 保持するもの

READMEは利用の入口、RESEARCHは結論と調査全体の索引、実験の索引は実験IDと状態を保持します。主題の本文は一つの場所へ置き、親に短い要約と適用条件、子に戻りリンクを残します。AGENTSには短い原則を、SKILLには判断と移動・検査の手順を置きます。

分割は目的、読者、主題、手順、証拠、参照の意味単位で行います。条件、失敗・中止・訂正、原典と固定版、hash、license/NOTICE、source closureを移動前後で照合します。旧パスや見出しへの参照は、元の場所の短い案内とanchorで維持します。

上流原文、法的文書、生成証拠、一体性が必要な記録だけは、正確なパス、種別、上限、理由のある例外を設けられます。不要な例外、重複、理由の欠落、存在しない対象、許容値の超過は失敗です。例外の一括指定や自動更新は行いません。

## 検査と制約

`.github/scripts/check-document-size.py` はGitの追跡対象を読み、UTF-8のバイト数と例外を検査します。Gitのsubmoduleとシンボリックリンクの本文は重複走査しません。必要なツール、ファイル、設定、UTF-8を確認できなければ失敗します。20,000バイト超の警告は、意味単位の判断を促すもので、CIを失敗させる条件ではありません。

サイズ検査は意味の保持を証明しません。リンク・anchor、文字範囲、yomiyasuの検査と、移動前後の読取りを併用します。既存の大きな実験記録を行数で一斉に切らず、改訂する主題から検討します。手順は[document-structureスキル](../../.agents/skills/document-structure/SKILL.md)にまとめています。
