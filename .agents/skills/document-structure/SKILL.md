# document-structure (文書の構成と分割)

長さを短くすること自体ではなく、読者が目的を達成できる単位に整えます。既存文書の内容を移す前に、役割と根拠を調べて分割先を決めてください。規則は AGENTS.md の9章、採用理由は [文書構成の調査](../../../docs/research/document-structure.md)にあります。

## 1. 最初に確認すること

文書の読者、目的、結論、操作手順、参照先を確認します。利用者の操作、開発者の保守、調査の採否、実験の再実行が混ざっていれば、読者の目的で分けます。技術の比較、事前の基準、結果、制約を切り離すだけの分割はしません。

Git で追跡する Markdown は、UTF-8で20,000バイトを超えたら分割を検討し、40,000バイトを超えたら分割または理由付き例外を必須にします。サイズは `python3 .github/scripts/check-document-size.py` で確認できます。行数や文字数では判定しません。閾値未満でも、主題が異なれば分けます。

## 2. 入口と分割先を決める

| 文書 | その場に残す内容 | 詳細の置き場 |
|---|---|---|
| README.md | 目的、対応状況、起動と利用の入口 | 主題ごとの利用・開発文書 |
| RESEARCH.md | 各結論と制約の要約、7章の全調査索引 | `docs/research/` の主題別文書 |
| 実験の索引 | 実験ID、目的、状態、記録へのリンク | `docs/experiments/` の各実験記録 |
| 実験記録 | 目的、固定条件、事前基準、結果、採否、失敗と制約 | 同じ実験IDの配下の独立した試行、付表、生データ |
| AGENTS.md | 短い必須規則とスキルの入口 | `.agents/skills/` の手順 |

親には結論と適用条件、読者が進めるための文脈を残します。「詳細はこちら」だけに置き換えず、何を読めるか分かるリンク名にします。分割先には親の索引への戻りリンクを置きます。文書の置き場を並立させず、同じ本文を複製しません。

## 3. 移動と保持の照合

1. 移動前の見出し、他文書からのリンクとanchor、実験ID、コマンド、原典、固定版、hash、否定条件を一覧にします。
2. 一つの読者目的・主題・手順・証拠として読める範囲を選びます。文書全体の移動は `git mv`、節の抽出は前後の対応を確認できる差分にします。
3. ファイル移動後の相対リンクを直し、入口の索引へ登録します。既存の公開パスや見出しは、元の場所に短い案内と必要な見出しまたは明示的anchorを残して保持します。
4. 移動前後を照合します。目的、前提、入力、操作、正常時と失敗時の結果、採否、制約、原典とlicense/NOTICE、source closureが全て追えることを確認します。数値や引用の訂正が必要でも、移動に混ぜて消さず、訂正理由を残します。
5. 親の要約と子の本文を同期します。古い状態と現在の状態、成功と容量超過、frontend非対応、未検証を混同しません。

禁止する分割は、行数での切断、見出しや表の途中での切断、必須の否定条件をリンク先へ追い出す分割、閾値を避けるだけの細片化です。目的、条件、失敗記録の読みにくさが残っていれば、サイズ検査の成功だけで完了にはしません。

## 4. 例外の扱い

例外リスト `.github/document-size-allowlist.tsv` は `path`、`kind`、`max_bytes`、`reason` の4列をタブで区切ります。対象は正確な相対 Markdown パスです。glob、親への移動、シンボリックリンクの指定は使えません。

種別は、上流原文の `upstream`、法的文書の `license`、生成証拠の `generated-evidence`、一体性が必要な記録の `indivisible-record` に限ります。40,000より大きい許容バイト数と、分けられない理由・原典を記録します。「長いから」だけを理由にしません。上限の自動更新や、種別だけで対象を一括除外する処理は加えません。

例外のない上限超過、理由の欠落、未知の種別、重複、対象の不存在、上限超過、不要になった例外は検査を失敗させます。分割で40,000バイト以下になったら、その例外を削除します。UTF-8不正や読取り失敗も失敗です。Gitのsubmoduleと追跡したシンボリックリンクは、本文を重複走査しません。

原文のライセンス、CSV、hash manifestを短くするために改変しません。CSVの既存の大きさの目安など、別形式の規則も維持します。既存の20,000バイト超の実験記録は改訂時に意味単位を検討し、数値だけで一斉に分割しません。

## 5. 検査と提出

```sh
python3 .github/scripts/check-document-size.py
sh tests/check-document-size/run.sh
python3 .github/scripts/check-links.py
sh tests/check-links/run.sh
python3 .github/scripts/check-jisx0213.py
python3 .agents/skills/yomiyasu/scripts/yomiyasu_lint.py <file>
git diff --check
```

新規ファイルも Git の追跡対象へ追加してから検査します。検討基準の警告は失敗ではありませんが、分けるか維持するかを意味単位で判断してください。旧パスとanchorを実際に確認し、移動前後の対応で根拠や失敗記録が失われていないことも読みます。

AGENTSとSKILLを改訂したら、スキル表と `.claude/skills/document-structure` のリンクも確認します。入口、本文、旧リンク、全条件と証拠の保持、サイズと例外、リンク、文字範囲、読みやすさが揃って完了です。
